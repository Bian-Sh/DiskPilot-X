## 结果（用户可见目标）

用户在清理视图里一次勾选多个目录，或让助手跨多个目录整合清理候选时，**应当只看到一份逐步累积起来的推荐清理清单**，而不是被反复要求决策"是否覆盖已有扫描结果"；助手不应在同一个失败原因上空转十几轮；任何一轮失败时，用户应能在会话里读到**为什么失败、已经做到哪一步**。

## 范围

1. 无头多范围批次（`analyze_paths`）的扫描器就绪等待、批次累积与数据生命周期。
2. `publish_recommendations` 的 append / 覆盖语义与空清单处理。
3. 技能任务面板的参数采集入口精简（首个弹窗改为对话内 `ask_user`）。
4. 模型侧失败的可读性与重试策略，含失败原因持久化。
5. 工具错误文案的可操作性，与重复失败循环的打断。
6. 会话标题生成时机与历史列表读取成本。

## 非目标

- 不改删除执行的安全边界：清理仍必须由用户在清单上确认后才执行。
- 不引入新的清理规则语义、不改 `RecommendationEngine` 的保护与排除判定口径。
- 不重做技能源码编译与单文件发布兼容性（AGENTS.md 已约束）。
- 不处理 `ai-first-loomx-harness` / `chat-model-list-identity` 等他人会话的陈旧 change 记录。
- 不重复实现已由 `diskpilot-data-home-20261030` 合入的数据目录统一与中文 JSON 可读化。

## 需求条目

### R1 无头批次必须能真正容纳多个范围

**现状**：`AnalyzePathsAsync` 在同一批内逐个调用 `ScanHeadlessAsync`，而后者在 `!_fileScanner.IsReady` 时直接抛 `InvalidOperationException("扫描器正在准备，请稍后再试。")`（[MainViewModel.cs:241](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/ViewModels/MainViewModel.cs#L241)）；`IncrementalFileScanner.IsReady => _pendingIndexBuild is null or { IsCompleted: true }`，第一个路径扫完正触发索引重建，于是同批后续路径**必然**失败并被记进 `batch.Errors`（[MainWindow.Copilot.cs:281-285](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L281)）。附件会话里模型自己归纳出"每次调用只有首个路径被成功扫描登记"。

**现状**：批次是单槽覆盖 —— `_analysisBatch = batch`（[MainWindow.Copilot.cs:289](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L289)），分多次 `analyze_paths` 时只有最后一批可被发布。

**需求**：

- R1.1 同一批内的多路径扫描必须**等待扫描器就绪后继续**，而不是把"正在准备"当成该路径的永久失败。等待要有上限，超时才记为失败并说明等待了多久。
- R1.2 一次用户目标（同一轮对话内的"把这些目录整合进清理清单"）中多次 `analyze_paths` 的**已登记范围必须累积**，发布时按路径前缀归属到各自范围；不得因为后一次调用而使前一次的范围不可发布。
- R1.3 批次返回必须显式列出**未登记成功的路径与原因**，让模型一次就知道缺哪几个，而不是靠"再调一次看看"。

### R2 发布语义：append 与覆盖二选一，且不得静默清空

**现状**：`scan_id` 命中批次时走批次分支（`merged.Count==0` 会报错，[MainWindow.Copilot.cs:137](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L137)）；`scan_id` 是主会话时走非批次分支，**没有**"零候选"守卫：候选全被 `not_scanned` 过滤后仍 `SetExternalRecommendations(空列表)` 并返回 `ok:true`，把面板替换成空（[MainWindow.Copilot.cs:161-170](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L161)）。附件会话正是这样：10 个候选全部 `not_scanned`，面板空，模型继续空转。

**现状**：非批次分支在 `mode!=merge` 且面板已有清单时，弹一个"替换当前清理建议"模态要用户当场决定（[MainWindow.Copilot.cs:156](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L156)）。用户反馈：这种目标导向的整合**不该反复弹窗让用户决策**。

**需求**：

- R2.1 追加 / 覆盖是一次性的用户选择（会话内记住，或在本轮首次发布时问一次），不得每次发布都弹模态。
- R2.2 传入候选数 > 0 而实际接受数 == 0 时，必须返回失败并保留原面板，绝不能返回成功并把清单清空。
- R2.3 `scan_id` 既不是当前主会话也不是任何在册批次时，错误信息必须带上"当前在册批次 id 与其范围数"，让模型一步改对，而不是回去猜。

### R3 技能参数采集回到对话，去掉首个弹窗

**现状**：`unity-cache-check` 自带 `ui.xaml` 只要 `roots` + `depth`；宿主发现面板里没有 `scope_path` 控件时，**再注入一个"本机范围"文本框**（[SkillTaskWindow.cs:58-65](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/Views/SkillTaskWindow.cs#L58)），值默认取 Treemap 当前根（[MainWindow.Skills.cs:51](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Skills.cs#L51)）。于是用户面对：任务面板弹窗（roots/depth/本机范围）→ 预览又要过扫描确认 → 结果视图又一个窗口。用户判断：首个弹窗只是要路径和层数，**这个行为完全可以在对话里用 `ask_user` 完成**。

**需求**：

- R3.1 当技能参数只是"路径 + 数值"这类可线性回答的输入时，默认走对话内 `ask_user` 采集，不打开任务面板窗口。
- R3.2 宿主注入的 `scope_path` 文本框不得在技能已自行采集范围时再出现；只有技能声明需要该字段时才要求它。
- R3.3 任务面板保留给"确实需要复杂表单/勾选矩阵"的技能；两条入口（面板 vs 对话）对同一个技能必须二选一，不得同时呈现给用户。
- R3.4 精简后 `unity-cache-check` 的既有安全约定不得退化：roots 为空或非法时仍返回空结果并说明原因，绝不扩大到全盘。

### R4 失败轮次必须可读、可恢复

**现状**：日志 694-728 行显示 429 RateLimited 以 1/2/4/8 秒重试 5 次（约 16 秒）后放弃；另两次失败是首轮已完成、第 2 步已收到流式事件后中断，[AgentLoop.cs:379](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/TinyHarness/AgentLoop.cs#L379) 的 `if (!retryable || receivedEvent || attempt == 5)` 直接抛，半成品轮次作废。用户侧只留下一个空白红色气泡（快照里 `IsError=true`、`Text=""`、`Segments=[]`），唯一出路是打"再试"。原因只进瞬时横幅 `ErrorMessage`，不进 `SavedChatMessage`，重开会话即丢失。

**需求**：

- R4.1 失败原因（状态码语义 + 已重试次数 + 建议动作）必须写进该条助手消息正文并随快照持久化，重新打开会话仍可见。
- R4.2 已产生流式内容后中断时，保留已产出的部分并明确标注"本轮未完成"，不得整体丢弃。
- R4.3 限流类失败的重试窗口要能吸收服务端 `Retry-After`，而不是固定 16 秒内 5 次。

### R5 工具错误要可操作，重复失败要打断

**现状**：`ask_user` 校验失败只说"用户决策请求包含未知属性。"（[UserDecisionRequestParser.cs:117](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.Core/Models/UserDecisionRequestParser.cs#L117)），不指出是哪个 key、允许哪些 key —— 附件/本机会话里模型为此多花整轮和上万 token。`get_analysis_evidence` 的"尚无允许分析的扫描结果。""分析范围不在当前扫描树中。"同样不给下一步。快照里同一组 4 个路径以完全相同的错误重试了 3 遍（seg5-8 / 15-19 / 33-36）。现有的重复发布守卫只在 `IsAnalysis` 且 JSON 完全相同时生效（[DiskAssistantService.cs:396](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.Core/Services/Assistant/DiskAssistantService.cs#L396)）。

**现状**：`ValidateAnalysisCommit` 在确认窗口之后才校验规则/偏好/隐私是否变化，长轮次里极易误伤并回抛"确认期间规则、偏好或隐私条件改变，原列表已保留，请重新分析。"（[MainWindow.Copilot.cs:165](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/MainWindow.Copilot.cs#L165)）—— 用户提到"总是各种奇怪的报错（比如目录确认期间发生变化）"。

**需求**：

- R5.1 参数校验类错误必须回带：出错的字段名、允许的字段集合、以及一个可直接照做的修正建议。
- R5.2 同一轮内"同工具 + 同参数 + 同错误"连续重复达到上限时，宿主必须终止该分支并给出终止说明，不得继续消耗 token。
- R5.3 一致性校验要说明**具体哪一项**变了（规则 / 偏好 / 隐私 / 扫描），并区分"必须重做"与"可以带着提示继续"。

### R6 会话标题与历史列表

**现状**：标题只在 `result.State == Completed && 文本非空` 时触发（[ChatViewModel.cs:244](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/ViewModels/ChatViewModel.cs#L244)），取消/失败轮永不生成 —— 附件 `Title=null`。同一会话内首次生成超时后 `titleCancellation` 非空即不再重试（[ChatViewModel.History.cs:24](file:///D:/AppData/Visual%20Studio/Projects/DiskPilot-X/src/DiskPilotX.App/ViewModels/ChatViewModel.History.cs#L24)，仅在 `ResetConversationUi` 复位）。`ConversationStore.List()` 为渲染一行标题把每个快照全量反序列化（本机 46 个文件 / 11.4MB）。`SaveConversation` 每次写 `DateTimeOffset.UtcNow`，仅打开会话也会改写 `UpdatedAt` 并重排列表。

**需求**：

- R6.1 首轮结束（含失败与取消）即产生可用标题：模型生成失败时回退到用户首句，不得长期留空。
- R6.2 同一会话内标题生成失败要允许再次尝试（受次数上限约束）。
- R6.3 历史列表不得为取标题而全量解析每个会话正文。
- R6.4 `UpdatedAt` 只在真实新增消息时推进；打开、恢复、重放不得把会话顶到列表最前。

## 验收项（草案）

- A1 一次勾选 ≥3 个互不重叠目录并交给助手：全部范围都完成扫描登记，无"扫描器正在准备"造成的丢失。
- A2 同一轮内分多次 `analyze_paths` 后一次发布：先前范围仍可发布，最终清单包含全部已登记范围的候选。
- A3 构造"候选全部被 `not_scanned` 过滤"：返回失败、面板保留原内容、模型收到含在册批次 id 的提示。
- A4 追加/覆盖只询问一次；第二次发布不再弹模态。
- A5 `unity-cache-check` 在对话中用 `ask_user` 收 roots 与 depth，不再出现首个任务面板弹窗，且不再有宿主注入的范围文本框；空/非法 roots 仍返回空结果且不扩盘。
- A6 断网或 429 造成中断：会话里能读到失败原因与已完成部分；重开该会话仍能看到。
- A7 同一工具同一参数同一错误重复到上限即被终止，不再产生新的空转轮次。
- A8 打开一个已完成的会话不会改变它在历史列表中的位置。
- A9 历史列表在 46 个会话 / 11.4MB 规模下不逐个反序列化正文（以代码路径或计数断言证明）。
