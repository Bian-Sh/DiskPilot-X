# 历史对话规格

## 目标
用户可在应用重启后加载以前的对话并继续交流，历史入口集成于新增会话按钮。

## 能力与场景

### Scenario: 自动保存与恢复
验收：A1
非空对话保存在本机，重新启动后历史仍可访问；加载后恢复用户消息、助手文本、思考和工具展示，继续提问携带原模型上下文。

### Scenario: 复合新增按钮
验收：A2
只保留一个复合按钮；左侧约90%主体用于新建会话，右侧小区域显示“∨”，点击打开历史列表。新建会话保留旧会话。

### Scenario: 历史列表
验收：A3
按更新时间倒序显示首条用户消息生成的单行标题及时间；空列表提示暂无历史，长列表可滚动，选中后加载并关闭弹层。

### Scenario: 运行与恢复边界
验收：A4
当前任务运行期间不能新建或切换；取消与失败可保存并继续；损坏历史不会导致崩溃或覆盖当前对话；恢复不重放操作，不恢复旧确认卡或磁盘引用。白名单改变后旧模型上下文不会带入新请求，API Key不进入存储结构。

### Scenario: 验证与发布
验收：A5
完成持久化与视图模型测试、Release构建及目标应用窗口验证；重新打包到outputs的可读时间目录。
