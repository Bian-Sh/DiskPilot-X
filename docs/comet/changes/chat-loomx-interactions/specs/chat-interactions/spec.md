# 聊天交互

聊天窗口必须清楚区分本轮执行过程和最终答复，提供可读参数、准确时间与可回查的完整过程。适用于用户气泡、助手响应、思考与工具调用，以及历史会话恢复。

## 运行计时与终态

过程区从本轮响应开始计时，每秒更新；最终正文完整输出后冻结。失败与取消分别保留真实状态，所有终态都停止计时。刷新不应重置用户展开选择。

### Scenario: 响应耗时随运行更新并在结束后冻结
验收：A1

给定一次真实助手响应开始，当流式内容和工具事件持续到达，过程标题持续更新耗时；当最终正文完成、失败或取消，耗时冻结并显示对应状态。

## 最终正文与过程折叠

完整内容必须按真实顺序保留。阶段性正文、思考和工具调用归入可重新展开的过程区，最终正文单独可见。带工具调用的 assistant 消息不构成最终答复。

### Scenario: 多步执行结束时收起前置过程
验收：A2

给定先思考、再输出中间说明、调用多个工具、最后输出最终正文的一轮响应，当无工具调用的最终 assistant 正文完整输出时，过程区默认折叠，最终正文仍可阅读；用户可展开回看所有过程。工具完成事件不会提前触发整轮折叠。

## 思考阅读

长思考必须在有高度上限的容器内独立滚动。处于底部时跟随新内容，上翻时保持位置，回到底部时恢复跟随。

### Scenario: 思考滚动遵循用户阅读位置
验收：A3

给定持续追加的长思考，当用户位于底部时看到最新内容；当用户上翻时新增内容不抢回底部；滚动到边界后可以继续操作消息列表。

## 工具参数可读性

工具参数应在既有安全投影之后展示为美化后的 JSON，直接显示中文与可读字符。路径、转义、嵌套结构和敏感值安全处理保持原语义；无效 JSON 保留原文。

### Scenario: 中文工具参数直接可读且语义不变
验收：A4

给定中文、嵌套 JSON、emoji、Windows 路径和需要脱敏的参数，当用户展开参数详情时直接看到可读字符，结构与转义语义正确，敏感值仍不可见；无法解析的内容仍可查看。

## 复制操作

复制按钮以图标呈现，并保留中文提示、无障碍名称和对应消息正文的复制行为。

### Scenario: 通过图标复制用户或助手正文
验收：A5

给定用户或助手消息，当悬停复制图标时可见中文提示，点击后剪贴板中包含对应正文。

## 时间与历史

每条气泡记录并显示创建时间，完整日期时间可通过悬停查看；完成时间单独记录，完成不能覆盖创建时间。会话恢复保留耗时、终态和最终正文边界。

### Scenario: 创建时间与完成时间独立保存
验收：A6

给定一轮持续数秒的响应，当响应完成并重新打开历史会话时，创建时间保持不变，完成时间与冻结耗时恢复一致。

### Scenario: 兼容旧历史并保留真实终态
验收：A7

给定缺少新增字段的旧历史文件，当打开会话时，原有正文、工具结果和顺序仍可查看；不推测已经丢失的时间，取消或失败不显示为成功。

## 交付验证

自动化检查和独立验收须覆盖消息生命周期、持久化及界面行为。独立应用必须提供新发布包，产物位于 outputs 并使用本地可读时间命名。

### Scenario: 可运行发布包完成应用窗口验收
验收：A8

给定本次实现候选，当相关自动化检查和独立验收完成后，提供经 cua-driver 验证的 Windows 发布包，证据仅包含应用窗口。

## 空态候选入口

候选入口必须用带背景的胶囊按钮呈现，提供清晰的悬停、按下及键盘聚焦反馈，保持原有提示词与操作行为。

### Scenario: 空态候选表现为可点击按钮
验收：A9

给定没有消息的聊天窗口，当用户查看创建规则、查看规则、空间检查和已有规则入口时，可以通过胶囊背景和反馈识别其可点击性；键盘可聚焦，点击仍触发对应提示。
