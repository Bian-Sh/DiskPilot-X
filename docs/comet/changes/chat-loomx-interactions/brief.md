# 目标

参照本机 Loom-X 已有的聊天交互，使 SpaceMonger 的 chat 窗口同时具备运行计时、最终内容完成后的过程折叠、思考独立滚动、可读的中文工具参数、图标复制按钮和可持久化的气泡时间。

# 范围

一次助手响应保留按顺序记录的消息分段，在展示层提供过程区与最终正文。过程区包含本轮思考、工具调用和最终正文之前的阶段性文字。运行时显示“处理中 12s”，最终正文完整输出后显示“已完成 12s”并默认折叠；用户可重新展开查看完整记录。计时以本轮真实开始和结束时间为准，每秒刷新，完成后冻结。

思考区使用有高度上限的独立纵向滚动容器，内容追加时只在读者位于底部时跟随，主动上翻时保留阅读位置。工具参数在现有安全投影之后统一美化 JSON，汉字直接展示，无法解析的文本保留原文。复制按钮显示图形并保留中文提示和无障碍名称。聊天空态的所有候选入口使用带背景的胶囊按钮，提供悬停、按下和键盘聚焦反馈，保留原有提示词与触发行为。用户与助手气泡均显示创建时间，悬停查看完整日期时间，完成时间独立记录。历史会话还原创建时间、完成时间、耗时与最终内容边界，兼容缺失新增字段的旧记录。

# 非目标

不更换应用主题，不重构 Agent 协议、模型调用或工具执行逻辑，不修改 Loom-X，不处理其他会话产物，不提交、合并、推送或清理用户现有文件。

# 约束与决策

- 独立 worktree 与分支 `codex/chat-loomx-interactions` 已建立，原目录未提交改动保持原状。
- Loom-X 是 Avalonia，当前应用是 WPF；复用交互逻辑与图形路径，按 WPF 现有组件实现。
- 参照 Loom-X：带工具调用的 assistant 完成事件仍属于中间步骤；无工具调用且有最终正文的 assistant 完成事件才结束过程区；若协议仅提供任务结束事件则以真实终态兜底，失败和取消分别显示状态。
- 自动折叠只发生在终态转换，后续增量与计时刷新不得覆盖用户主动展开或收起的选择。
- 工具参数只处理现有安全投影后的显示文本，不改变实际发送参数，不通过正则盲目反转义路径或字符串。
- 创建时间不得再被完成时间覆盖。旧记录已经丢失的原始创建时间不伪造，按记录中现存时间展示。
- 验收优先使用 cua-driver，只截取应用窗口；发布包通过 Start-Process 隐藏启动并校验进程路径。

# 验收示例

- A1：发送消息后，助手过程区每秒更新耗时；最终正文完成时冻结耗时。失败和取消停止计时并显示真实状态。
- A2：同一响应包含思考、中间正文和多轮工具调用时，最终正文完整输出后，之前内容默认折叠，最终正文继续可见；手动展开可查看全部原始顺序；中间工具消息完成不得提前收起整轮。
- A3：长思考不会无限撑高消息区，滚动条可以浏览全部思考；底部跟随新增内容，主动上翻后阅读位置保持，回到底部后恢复跟随；不破坏外层消息列表滚动。
- A4：包含“中文目录”、嵌套中文字符串、反斜杠 Windows 路径和 emoji 的工具参数直接显示可读字符，保持 JSON 层级与语义；敏感值仍脱敏，无效 JSON 原文可查看。
- A5：用户与助手消息复制操作均呈现图标，保留中文 tooltip 与无障碍名称；点击后复制对应正文，图标不占用大段文字空间。
- A6：用户与助手气泡均显示创建时刻，悬停显示完整日期时间；完成响应后创建时间不变，另存完成时间与冻结耗时；重新打开会话后保持一致。
- A7：缺失新增时间或最终边界字段的旧会话仍可打开；已有消息正文、工具结果和顺序不丢失，终止状态不伪装成功。
- A8：相关自动化检查通过，并使用独立验收会话核对全部验收项；通过 cua-driver 验证新发布包中的过程折叠、思考滚动、中文参数、复制图标与时间显示，输出带本地可读时间的发布包。


- A9：聊天空态的创建规则、查看规则、空间检查与已有规则候选均具有明确的胶囊背景、圆角及悬停/按下反馈，文字可读，键盘可聚焦，点击仍填入并执行对应提示。
