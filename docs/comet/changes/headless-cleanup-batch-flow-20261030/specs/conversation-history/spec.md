# 历史对话规格

## 目标

应用重启后可加载历史对话并继续交流，标题及时可读，浏览不改变排序，历史入口不因正文体积增长而每次全量读取。

## 既有完整行为

- 非空会话在本机原子保存，恢复用户消息、助手文本、思考、工具过程和原模型上下文；继续提问使用修复后的原上下文。
- 保留一个复合新增会话按钮，主体新建并保留旧会话，右侧下拉显示历史。按内容更新时间倒序显示单行标题和时间，暂无历史提示、长列表滚动、选中加载关闭保持。
- 运行期间禁止新建和切换；取消与失败可保存并继续。损坏文件不能崩溃或覆盖当前对话。
- 恢复不重放操作，不恢复旧确认卡、磁盘对象、扫描批次或删除授权。扫描入口的纯元数据可恢复，再根据当前进程缓存重新判定可用性；这不等于持久化或恢复扫描树。白名单改变后旧模型上下文不带入新请求，API Key 不进入存储。
- JSON 中文可读性和数据根目录沿用当前产品行为，不新增自动迁移或旧品牌数据访问。

### Scenario: 立即标题与有限重试
验收：A15
首轮成功、失败、取消都能立即得到用户首句生成的非空回退标题。模型标题异步生成失败后可在后续真实消息时再试一次，同会话总共最多两次；成功后替换回退标题，失败不阻塞保存。重置标记不能导致无限重试。切会话后旧请求只能取消或写回其原会话，不能污染当前会话。

### Scenario: 内容时间与浏览行为分离
验收：A16
保存快照不等于有新内容。仅打开、恢复、重放、更新标题或退出保存不推进内容更新时间，不顶到历史列表首位；新增消息或真实推进消息内容才推进更新时间。恢复后继续发送消息可正常更新，标题异步完成不覆盖其他会话的排序或内容。

### Scenario: 轻量摘要读取与局部修复
验收：A17
列表使用小型摘要，不为每一行反序列化完整 Messages/ModelMessages。旧会话可在首次缺失摘要时局部建立摘要，此后常规列表不逐份读取正文；正文有变化能检测并更新，摘要缺失或损坏仅重建相应项。摘要写入失败不得破坏正文或现有列表中的其他条目，删除同步处理相关摘要。既有用于隐私授权的 ConversationMetadata 核验语义保持独立，不能把展示摘要当授权证据。使用 46 个、约 11.4MB 合成会话和读取计数验证，不依赖真实用户会话或仅凭耗时推断。

## 验证要求

会话存储、视图模型、故障和排序回归与真实发布应用窗口验收保持。标题、失败持久化、正文与摘要回退须在独立临时数据目录验证；不直接改写真实 AppData 会话。
## 扫描入口记录

按 scan-snapshot-navigation 完整目标规格显示历史卡片；同进程缓存命中可查看，重启或回收后显示明确失效原因及显式重扫入口。不得因缓存不存在而丢弃历史卡片、自动扫描或请求模型；快照引用不计作旧执行授权，普通消息及旧版记录兼容性保持。相关验收归属 A19-A24，不重复生成验收项。
