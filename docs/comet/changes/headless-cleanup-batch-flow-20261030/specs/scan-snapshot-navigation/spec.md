# 扫描快照与对话导航规格

## 目标

为所有宿主技能提供多路径无头扫描能力：真实扫描树只留内存，不必显示在 Treemap；对话中每个范围保留入口，由用户按需查看。入口可以持久化，内存快照和清理授权不因此持久化。

## 架构与最小契约

优先复用主窗口既有 AI 扫描缓存和显示路径，不建立独立扫描引擎。缓存中每份成功结果有唯一 snapshot_id、所属会话/来源、缓存代次和扫描时间；根路径只用于查询和标签，不作为跨版本身份。不同根路径或同根不同版本不得共用标识。

消息保存 ScanSnapshotReference 一类纯数据：标识、缓存代次、根路径、扫描时间、总大小和条目统计。具体类型名可沿用工程命名；不持久化 ScanSession、FileEntry 树、控件、回调或旧用户许可。实时可用性在打开历史、点击与安全设置变化时重新计算，不把保存时的 available=true 当当前状态。

查看缓存可跨同进程会话切换；用于发布/清理的分析批次和授权仍限当前会话。显示旧扫描只是查看历史快照，不将旧模型上下文带入新会话、不自动允许使用旧结论删除。缓存引用和现有清理证据共享必要的所有权管理，不能静默回收活动证据。

### Scenario: 多范围无头扫描与独立入口
验收：A19
一次扫描多个允许范围，成功范围逐项注册快照并把入口追加到对应对话消息，失败项展示原因。扫描过程中和完成后均不强制切换主 Treemap。入口显示范围、时间、占用及“扫描快照，非实时”提示。默认工具结果为批次标识、快照标识和有界统计，不自动附带完整扫描树/长 evidence；分析只在确有需要时按范围取证。

### Scenario: 点击显示且不重复工作
验收：A20
用户点击有效入口后，按精确 snapshot_id 取缓存，同步 Treemap、TreeView、路径与统计，保持一致的扫描上下文。切换两个范围或同范围不同版本都展示各自快照。点击不调用扫描器、不发模型请求、不发布清单、不执行删除、不恢复旧授权。页面明确显示快照时间，不宣称磁盘当前状态。展示切换不可绕过正在进行的任务或现有工作区替换保护。

### Scenario: 同进程历史恢复
验收：A21
离开会话后再次打开，保存过的扫描入口仍存在；对应缓存还在且当前条件允许时可查看原快照。只恢复入口元数据，旧版本快照文件没有新增字段也正常加载。入口与普通文本、错误段、技能结果窗口独立，不依赖重建旧 SkillTaskCard、重放工具或重新运行模型。

### Scenario: 重启后明确失效与显式重扫
验收：A22
缓存代次不匹配时，入口保留并显示“内存结果已释放，需要重新扫描”；不得静默消失或伪装可用。用户点击重新扫描才请求当前范围的只读扫描，按当前隐私、范围和确认规则执行；产生新快照和新时间，原历史记录不改称新结果。取消不执行下一步，重扫不自动请求模型或发布/删除；打开会话不自动重扫。

### Scenario: 失效、预算与忙碌状态
验收：A23
缓存使用明确可测试的预算和最近使用回收策略，避免无限保存历史树；当前展示和必需活动证据不能被静默回收，无法安全接纳新结果时说明限制。入口区分进程重启、预算回收、路径不存在/不可访问、当前安全限制、任务繁忙；没有确认具体原因时用中性“结果不可用”，不猜测。

隐私/扫描限制变更后不得从旧卡片绕过访问或向 AI 泄漏路径。限制可能解除时可重新判定，但不重获清理授权。删除会话不会影响其他会话或当前工作区所需缓存。历史卡片只是记录，路径改动或旧时间不能作为现时可删除依据。

### Scenario: 宿主技能中的通用工作流
验收：A24
app-guide 用用户可理解的方式解释入口和失效，继续遵守“说明不自动触发动作”；disk-management 和 path-cleanup-recommendation 记录实际工具契约，先无头扫描、多范围累积、摘要返回、按需取证，用户按需点击展示。其他技能直接复用，不要求先替换主视图，不让模型生成伪按钮或自行拼快照入口，不默认覆盖原清单。工具与 UI 只共享稳定元数据，不为点击再次把完整目录树送入模型。

## 验证边界

回归使用临时目录和合成会话；比较扫描器、模型调用计数及各视图当前 session。覆盖同路径不同版本、切换会话、重启代次、回收、取消、安全变化与忙碌状态。GUI 只操作非提权测试应用窗口，发布验证继续执行主 brief A18。
