# 无头批次与推荐清理发布规格

## 目标与边界

在当前会话中将多个用户允许的目录扫描、分析并整合成一份推荐清单。不替换主工作区扫描视图，不直接执行删除。所有候选必须来自真实且仍有效的扫描证据，通过当前规则、保护和隐私约束。

## 批次生命周期

### Scenario: 多范围与扫描器就绪
验收：A1
同一次请求内按可控顺序扫描多个范围。扫描器因索引准备暂未就绪时，可取消地等待，并受明确上限约束；超时说明路径与耗时，不把瞬态准备状态直接当作该目录永久失败。主工作区 Treemap、文件树与原扫描会话不被替换。

### Scenario: 同会话累积与归属
验收：A2
当前会话只有一份可累积的工作批次，多轮和多次 analyze_paths 保留既有成功范围。每个成功范围登记稳定的查看快照标识；默认返回简要统计，需要时才读取该范围证据，不自动把完整扫描树发给模型。每个范围关联独立证据；重复路径复用或显式刷新，嵌套候选按最具体的有效扫描根确定归属，不用字符串前缀误匹配相邻目录。工具返回批次标识、已登记范围和真实统计；最终候选按规范化路径去重。

### Scenario: 取消、部分失败与失效
验收：A3
部分失败不丢成功范围，逐项返回成功、失败、未执行状态及原因。取消及时停止等待或扫描，不自动发布，保留仍有效的已完成范围。批次限当前会话，新建/切换会话或显式清空推荐清单时失效；应用重启不恢复旧扫描对象或执行授权。恢复历史后必须重新取得当前清理证据；历史查看入口可按 scan-snapshot-navigation 复用本进程缓存，仅供查看，不恢复批次或旧授权。

## 发布契约

### Scenario: 无可接受候选时保持原清单
验收：A4
批次和普通扫描发布使用一致的失败保留语义。输入为空、全部未扫描、全部受保护或被隐私限制过滤时，不修改现有清单并返回失败，说明提交数、接受数和拒绝类别。发布不是清空操作；有意清空须使用独立明确的用户动作。

### Scenario: 默认追加与幂等
验收：A5
未指定模式时默认追加，产品称 append，已有 merge 工具值映射为同一语义；保留已有建议，按规范路径去重，相同证据及候选重复发布不重复计数。追加并不豁免证据、隐私或保护校验。

### Scenario: 显式覆盖与授权有效性
验收：A6
覆盖只在用户明确选择后执行，显示影响但不删除文件。选择绑定当前会话、清单修订和安全上下文，同一有效事务内只确认一次；条件改变后撤销旧许可并说明原因。取消或未获授权时原清单不变。默认追加无需为模式另行打断对话。

### Scenario: 批次标识与诊断
验收：A7
无效或过期 scan_id 不被解释为当前主会话。错误包含稳定类别、可公开的当前批次标识、范围数和建议动作。不得返回已失效会话或被排除路径的信息；部分路径失败的诊断也受同一隐私约束。

### Scenario: 统一的安全提交边界
验收：A8
普通和批次发布在等待用户决定后、实际提交前都复核当前证据与条件。扫描失效、受影响规则/偏好、隐私或保护变化不能被忽略；能安全重校验的候选采用当前条件，并在必要时重取授权，否则失败保留原清单。无关显示项变化不导致误报，无法确定影响则安全失败。规则保护引擎语义不变；删除执行仍经过最终异步复核、当前清单修订与用户确认，异步边界之后重新核验授权，不用发布许可替代删除许可。

## 发布环境

### Scenario: 真实文件夹发布验收
验收：A18
除单元测试外，在非提权自包含测试包验证真实三范围分析与发布，动态源码验证和经授权的只读源码执行不依赖 SDK。测试 EXE 为 asInvoker，用户交付 EXE 为 requireAdministrator；核对实际嵌入清单及 DLL、skills 完整性。统一输出到主仓库的时间命名目录，保留完整文件夹，不提供 ZIP 或单文件包。不得把未验证的提权后 UI 声称为已通过。
