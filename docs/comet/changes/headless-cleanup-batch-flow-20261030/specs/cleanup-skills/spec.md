# 清理技能与助手交互规格

## 既有能力与安全边界

- 创建器、规则与资料持久化、校验和只读预览，兼容内置 Unity Skill。用户技能可以创建和更新，内置技能不可被修改或遮盖。
- 受约束 XAML 与可选可信 C# 源码继续可用，编译器随产品文件夹发布；可信源码执行前明确授权，不宣称安全沙箱，不引入 Python 或通用 Shell。
- 空态创建与查看规则入口、可滚动规则列表、保存后目录刷新、技能引用保持可用。文本和公开网址资料保留来源；无效、过大或受限输入明确失败。
- 规则只读试扫和候选来自本机真实扫描，不把资料或猜测当结果。技能不直接删除，复用宿主最终清单版本、保护与确认链路，取消不执行。
- XAML 仍拒绝任意 CLR 类型、事件代码和未允许的绑定。结果表格、筛选、图表与窗口能力不因参数入口精简而删除。
- ask_user 保留单选、多选、文本、数字、必填校验、其他答案和取消；答案返回同一模型任务，停止释放等待。

## 任务输入形态

### Scenario: 纯参数技能的单一对话入口
验收：A9
直接修改 Unity skill 的工作流，用 ask_user 收集 roots/depth，删除该技能首个 ui.xaml 参数面板与引用；不为此增加通用表单推断器或全局输入形态系统。必要时调整已有通用快捷文案，不再指示所有 provider 必须开面板。宿主不注入多余 scope_path，也不以 Treemap 当前根兜底扩大范围。同一技能一个任务启动入口，结果查看入口保留。取消不执行；空或非法 roots 返回空结果并说明原因，绝不扩到全盘。

### Scenario: 复杂交互与兼容能力保留
验收：A10
确需多列表勾选、矩阵、筛选等交互的技能保留面板；只在技能明确需要时要求宿主范围字段，不能用隐式注入替代范围声明。结果窗口及必要操作保持。回归已有创建、更新、资料导入、可信源码验证/执行、结构化提问与最终清理确认，内置 Steam 等复杂结果交互不受损。只修改实际需要的技能流程与冗余入口；不通过猜测 XAML 文本或新增全局输入形态配置来重造表单框架。


## Unity Library 的最小信息工作流

### Scenario: 只针对 Library 且默认最少回传
验收：A25
仍以 Assets 与 ProjectSettings 同时存在作为项目结构证据，仅将真实 Library 目录作为本轮清理候选；不再同时推荐 Temp、obj、Logs。项目本体、Build(s)、录制和快照仍不纳入候选。默认给 AI 的发现结果以 Library 路径列表和必要有界摘要为主，完整统计表/明细仅留本地结果视图；不因便于展示就向模型传整棵树。用户选择后可对 Library 路径直接复用通用无头扫描，按需取证、追加推荐，不要求展示到 Treemap。Library 可重建但有重新导入成本，保持 ReviewFirst，删除只经宿主清单和最终用户确认。

### Scenario: 活动与 Hub 线索按需且可证实
验收：A26
AI 确有判断需要时才获取最少本地线索：关联项目路径、可读的项目内容变化时间及其来源/局限、Hub 在册状态及证据类别。用户数据读取经过现有宿主能力桥和安全边界，不默认上传项目正文、文件清单或整份 Hub 数据。

“近期开发”不是单个目录时间可以证明的事实，Library 构建/导入写入也不能冒充用户最近开发。Hub 状态区分有记录、成功读取受支持来源但未列出、未知；缺失、无权、格式变化均诚实降级，不猜。Hub 不是项目发现的唯一来源，未列出不等于无用；活动时间旧不等于允许删除。AI 可解释建议和不确定性，但不能用这些线索绕过保护和最终确认。
## 验证与发布

保留现有自动化回归和真实应用窗口验收。发布使用完整运行时 DLL 与 skills，动态源码编译/只读执行在实际发布目录验证，不要求用户安装 SDK。测试与用户交付清单分别核对，规则同主 brief 的 A18。
