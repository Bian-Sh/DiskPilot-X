# 助手失败与恢复规格

## 目标

失败必须在会话中可见、可保存、可定位并能安全继续，不能以无限重复消耗请求，也不能因重试重复执行有副作用的工具。

### Scenario: 可读且持久的失败结果
验收：A11
429 耗尽、连接失败、响应超时、流中断与用户停止分别给出简洁中文原因和操作建议；展示本次重试次数、等待状态、已完成步骤与未完成步骤。没有最终文本时也保存错误或终止说明，不只设置 IsError 或只写日志。已有有效片段不丢失，重开会话仍可见；敏感响应、API Key 和凭据不得进入会话正文或模型可见诊断。

### Scenario: 有界重试与安全继续
验收：A12
保留请求层有界重试和服务端 Retry-After 提示，取消优先，等待和总次数有上限。认证、权限、额度及用户取消不自动重试。首个流事件后的中断不透明重放请求；保留片段，展示需继续的边界，继续时修复悬空工具调用而不重复已完成工具。超时不是成功，部分输出也不是全部执行完毕的证据。

### Scenario: 参数和上下文错误可操作
验收：A13
ask_user 的未知属性错误返回字段位置、未知字段、该层允许集合和合法修正示例；不借诊断暴露用户敏感原始值。缺少证据、范围不匹配、过期扫描、规则/偏好/隐私变化分别使用稳定错误类别，指出下一步是修正参数、重新读证据、重分析还是重取确认。对实际变化给出具体说明，不能统一误报“目录在确认期间变化”。

### Scenario: 重复失败终止
验收：A14
同一轮内，用工具名、规范化参数与稳定错误类别识别连续重复失败；参数对象键顺序不影响身份，参数数组有序语义保持。第三次相同失败后停止本轮自动工具循环，不发起第四次调用或后续空转模型轮次。终止说明包含失败原因和下一步并持久化。新轮次或已确认的真实进展可以重置，单纯错误文案或 JSON 键顺序改变不能重置；保留已有最大步数防线。

## 安全不变量

失败恢复不增加数据可见范围，不恢复旧清理授权，不自动执行被用户拒绝的动作。原清单及已完成范围仅在当前会话且仍满足安全条件时可复用；安全变化按照无头批次与推荐清理发布规格执行。
