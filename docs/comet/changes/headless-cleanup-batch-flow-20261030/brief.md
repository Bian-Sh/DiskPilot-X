# 目标

让用户选择的多个目录在不替换磁盘主视图的情况下，逐步形成一份真实、可追溯的推荐清理清单；失败时保留已完成结果、说明原因并停止无效循环。参数简单的技能直接在对话内提问；会话失败、取消和恢复后仍可理解、可继续。

用户在 2026-10-31 认可原四阶段推进方向，并补充通用无头扫描入口、历史失效交互和 Unity Library 收敛要求。原范围保留；新增完整交互规则仍待本轮展示后确认，未开始应用实现、发布、删除文件或 Git 交付。

# 范围

使用一个 Comet change 跟踪，按四个阶段顺序实现、分别收集验证证据：

1. R1/R2/R7：无头批次、范围累积、发布模式、不丢结果，以及内存扫描快照的对话入口和按需 Treemap 展示。
2. R3：直接修改 Unity skill 流程并删除首个纯参数 UI，目标收敛为 Library；复杂交互与结果窗口保留，默认向 AI 只返回必要路径和小摘要。
3. R4/R5：失败持久化、有限重试、错误可操作性和重复失败终止；安全校验贯穿第一阶段。
4. R6：标题回退、有限重试、稳定更新时间与轻量历史列表。

# 关键决策（待整体确认）

- D1：批次只属于当前会话，在同一会话的多轮请求中继续累积；新建、切换会话或清空推荐清单时失效。应用重启不恢复扫描对象或旧执行授权；失败/取消保留已完成且仍有效的范围，取消不隐式触发发布。这里的清理批次与查看快照分离，切换会话/清空清单不必清除仍在进程缓存中的查看快照。
- D2：未指定发布模式时默认追加。`append` 表示产品语义，现有工具值 `merge` 作为兼容映射保留；覆盖必须经过用户明确选择，只针对已展示的同一清单修订有效，清单或安全上下文变化后不得沿用旧覆盖许可。默认追加不新增一次无意义提问，同一授权内后续发布不重复弹模态。
- D3：修改 Unity skill 自己的流程，用 `ask_user` 收 roots/depth 并删除其首个参数 UI，不开发通用表单推断或为了它新增全局入口形态声明。复杂技能面板和结果视图保留，现有公共快捷文案不得强制所有 provider 先开面板。Unity 候选仅限真实项目的 Library，默认传回 Library 路径，完整表格留在本地。
- D4：涉及当前目标的扫描失效、隐私/白名单、保护与删除授权变化必须硬失败并保留原清单。无关显示项变化可继续。相关规则或偏好发生变化时，基于当前条件重新校验候选并重取必要授权，不直接忽略版本差异；无法证明无关时安全失败。批次和普通发布使用同一安全提交边界。
- D5：一个 change、四个顺序阶段，不启动多会话并行开发。实现与最终独立验证按 Comet 的角色边界执行。
- D6：同一轮内，同工具、规范化同参数、同错误连续失败三次后停止本轮自动工具循环；不发起第四次重复调用。只对已确认的实际进展重置计数，不把 JSON 键顺序变化当进展。
- D7：首轮失败/取消也立即使用用户首句作为可用标题；模型标题最多尝试两次，在后续有实质消息的时机重试，不后台无限请求。标题变更不改变会话内容更新时间。
- D8：保留现有请求级有限重试与服务端等待提示；首个事件后中断时保留片段并提供安全继续入口，不自动重放可能已执行的工具。凭据、权限、余额错误与用户取消不自动重试。

- D9：查看快照使用稳定的 snapshot_id 与进程缓存代次，不能只靠根路径选“最新结果”。每个无头成功范围自动附带一个宿主对话入口；完整 ScanSession 只留内存，消息只持久化标识、范围、扫描时间和简要统计，不把文件树写进正文或模型上下文。
- D10：同一进程切换历史会话后仍显示扫描卡；缓存命中且访问仍被允许时可点击查看原快照。重启、预算回收、路径不可用或当前安全设置限制访问时，保留历史卡并显示对应原因；重新扫描是明确的用户动作，不在打开历史时自动触发。重扫产生新版本，旧记录不冒充新结果。
- D11：点击可用卡片只切换 Treemap、TreeView 与相关扫描状态，不重新遍历磁盘、不请求模型、不自动发布/清理；标明扫描时间和“快照并非实时”。任务或删除操作繁忙时不抢占工作区。查看不恢复旧确认或将其他会话上下文带入 AI；内存回收有预算，活动展示及必要证据不得被静默撤销。
- D12：Unity “近期开发”只由按需读取的项目内容变化线索近似说明，并标明来源与不确定性，不把 Library/目录时间称为真实最近开发时间。Unity Hub 在册状态按需读取允许的本地证据，区分在册、未列出、未知；未安装、无权读、格式不支持不能推断为未在册。二者仅帮助 AI 解释候选，不构成可删除证明或自动授权。
# 约束与已核实证据

- 源码基线：`main` 的 `40147bae797c7744140201873ec0f9509f23e9fe`。实际源码位于本 change 的独立 Git worktree，分支 `codex/headless-cleanup-batch-flow-20261030`。Comet 在该工作树内以 `current` 绑定，不会据此自动合入主仓库。
- 主仓库的原需求草案是未跟踪文件，本任务只读参考，未搬走或覆盖。
- `AnalyzePathsAsync` 每次建立新批次并覆盖 `_analysisBatch`；`ScanHeadlessAsync` 在扫描器未就绪时抛异常。后者是异步索引时序风险，不能仅凭静态代码宣称同批后续路径“必然失败”。
- 普通发布分支没有接受候选为零的保护；批次分支虽有零候选保护，却没有普通分支的 `ValidateAnalysisCommit` 调用。必须测试两条路径，不能只给其中一条补丁。
- `TinyHarness/AgentLoop.cs` 已有最多五次请求尝试及 `Retry-After` 支持；`receivedEvent` 后禁止透明重试是防重复效果边界，不应直接移除此限制。
- `ConversationStore.List()` 通过 `Load()` 读取每个正文；现有 `ConversationMetadata` 服务隐私授权核验，不是历史摘要缓存。
- 标题请求标记会在会话重置时清空；问题是同一会话失败后不能重试，而非进程永久卡死。

- 本轮代码发现已有 `_aiScanSessionsByRoot`、`TryShowCachedAiScanForPath` 和主视图赋值路径，可复用；当前无头返回自动附带较长 evidence，需按需取证。`SavedChatMessage` 未保存技能卡片或快照入口，必须新增纯元数据而非序列化视图或扫描树。

# 验收示例

- A1：一次分析至少三个互不重叠目录，在扫描器延迟就绪的可控条件下都能登记；等待可取消、有上限，超时报告耗时及具体路径，不替换主工作区扫描视图。
- A2：同会话分两次分析不同目录后统一发布，早先范围仍有效；重复/重叠路径按明确归属去重，不产生重复候选或错误跨范围匹配。
- A3：部分范围失败或用户取消后，返回成功范围、失败/未执行范围及原因；保留完成范围，取消后不自动发布。切换、新建会话、清空清单后旧批次不能使用，重启不恢复旧授权。
- A4：普通发布和批次发布中，空候选或候选全部被过滤均不清空原清单；返回失败、原清单不变、接受数和拒绝原因可读；清空仅由显式清空动作完成。
- A5：默认追加保留已有建议，按规范路径去重且重复发布幂等；未声明模式也不默认覆盖。
- A6：用户显式选择覆盖时只确认一次，同一有效清单修订内不反复弹窗；取消、上下文变化或清单变化不复用旧覆盖许可，未授权覆盖保留原清单。
- A7：无效或过期 `scan_id` 返回可操作错误，携带当前允许公开的批次标识、范围数和下一步；不泄漏已被排除的路径或其他会话数据。
- A8：批次和普通发布都覆盖确认等待期间及提交前的扫描、规则、偏好、隐私和保护变化；相关变化安全重校验或失败保留，无关显示变化不误伤；最终删除仍需要当前清单版本和用户确认。
- A9：直接修改 Unity skill 流程，在对话内收集 roots/depth，并删除其首个纯参数 UI 与引用，不依赖新增通用表单推断；不注入多余的 scope_path，取消不执行，空/非法 roots 不扩盘且明确说明原因。
- A10：确需复杂表单的技能仍能使用面板，结果表格/筛选/清理确认不丢失；已有技能的创建、只读预览、资料、可信源码与结构化提问能力保持。
- A11：模拟 429 耗尽、断网、流中断和用户停止，当前会话明确展示错误类别、原因、重试情况及部分进度；保存恢复后仍可见，不含密钥或原始敏感响应。
- A12：可重试错误有明确次数与等待上限并遵从取消；凭据/权限/余额错误不自动重试；流中断后安全继续不重复完成工具，未完成工具调用能被修复，不误报已完成。
- A13：ask_user 未知字段错误指出字段、允许集合和修正示例；无证据、范围失效与安全条件变化分别给出具体类别和下一步，不用一个笼统错误覆盖所有情况。
- A14：同轮同工具同规范化参数同错误，第三次失败后停止自动循环、不发起第四次重复调用；键重排不能绕过，实际进展和新轮次按约定重置，并持久化终止原因。
- A15：成功、失败、取消首轮都及时得到非空回退标题；模型标题失败后允许后续一次重试且总计不超过两次，切会话后的旧请求不得写入新会话。
- A16：仅打开、恢复、重放、标题更新和退出保存不会改变内容更新时间及历史排序；只有真实新增或推进消息内容时更新时间，恢复继续提问后可正常排序。
- A17：用合成的 46 个会话、约 11.4MB 正文构造历史列表测试：摘要建立后的常规读取不逐份反序列化正文；缺失、损坏、陈旧摘要可局部回退/重建且不丢正文，不损害现有授权元数据核验。

- A19：一次无头扫描至少三个目录，主 Treemap 不变，各成功范围对应稳定版本的扫描入口；部分失败保留成功入口，卡片标注范围、时间、大小及快照性质，默认模型返回不含完整扫描树或自动大段证据。
- A20：点击任一可用扫描入口，仅复用对应快照切换 Treemap、TreeView 和扫描状态；可在不同快照间往返，同路径不同版本不得串用。扫描器/模型调用计数不增加，不隐式发布或删除，不自动恢复旧授权。
- A21：同进程切换离开会话再恢复历史，扫描入口仍显示；内存命中、当前访问允许时可查看。入口只保存元数据，旧记录无此字段也正常恢复，不能序列化整个 ScanSession 或依赖恢复技能窗口。
- A22：重启应用后历史入口仍显示，但标为“内存结果已释放，需要重新扫描”，不能假装可用。用户点重新扫描才启动受当前安全约束的扫描，新结果采用新标识/时间，取消保留旧记录，不自动请求模型。
- A23：缓存预算回收、路径失效、当前隐私/扫描限制、任务繁忙分别有准确状态；不越权、不抢占、不把已失效快照冒充当前磁盘或执行授权；回收不丢历史元数据，必要活动证据不能被静默回收。
- A24：宿主 app-guide、disk-management 与路径清理 skill 都记录同一通用契约：多路径可无头扫描，按需取证，用户通过对话入口显示快照，历史失效需显式重扫；不再声称必须先替换主视图或默认覆盖。其他技能亦可复用，不局限 Unity。
- A25：Unity 只提交真实 Library 目录作为清理候选，不再把 Temp/obj/Logs 混入本次目标，项目本体与 Build(s) 等用户产物仍受保护。默认给 AI 的结果仅必要 Library 路径和有界摘要，不回传完整文件树/完整表格；本地结果视图可保留，最终删除仍 ReviewFirst 并经用户确认。
- A26：AI 按需查询近期项目内容变化与 Hub 在册线索，返回有来源的有限字段，不传整份 Hub 清单/项目正文；不存在、无权读、版本不支持都如实标未知。未在 Hub 或时间较旧都不能单独证明可删除，不能猜真实最近开发时间。
