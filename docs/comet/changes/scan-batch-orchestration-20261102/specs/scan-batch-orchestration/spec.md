# 扫描与推荐批次编排
## 实时容量与背压
宿主公开每次路径和推荐上限、快照数量和条目预算、当前占用。超过限制必须明确失败，不静默忽略范围。被视图、分析或推荐保护的证据不可自动释放；容量不足时明确提示，不伪装可无限继续。
## 跨批证据和推荐
每批完成后返回独立扫描引用；后续追加能引用此前仍有效的证据。建立新清单和追加清单明确区分，合并保留旧勾选并消除重叠。安全策略和来源版本在后台校验与UI提交间发生变化时拒绝过期结果。
## 扫描列表
每轮扫描集合以紧凑cell列表显示。路径、待扫描、扫描中、成功、失败和失效明确区分；仅展示真实进度。高度自然增长至240 DIP，再内部滚动。有效快照才显示Treemap入口。
## 历史恢复
持久化元数据不是存活扫描实例。重启、缓存回收、路径不存在、权限或隐私限制时重新核验；失效记录不显示Treemap入口、不自动重扫、不恢复历史清理授权。受限路径不得通过历史列表明文泄露。
## 推荐发布性能
宿主执行稳定证据的后台校验和短UI提交；提交前核验策略、来源和清单版本，保留既有安全复核。避免每批重建整份可观察集合造成卡顿；发布完成后回执，未完成不接收下一批。
## 宿主引导
disk-management、path-cleanup-recommendation与app-guide说明登记范围、查询预算、串行分批扫描、按批分析、分批发布和等待回执。部分成功不能代表全任务成功，禁止自动删除清单或解除保护来腾容量。
## 交付约束
保留既有聊天、Treemap、推荐空态和Token修复；不新增顶部状态栏。自包含完整文件夹发布到主仓库outputs，分别验证测试asInvoker及交付requireAdministrator的实际清单，进行应用窗口UI和发布环境规则验收。
