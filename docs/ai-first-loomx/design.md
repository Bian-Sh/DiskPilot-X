## 依赖决策

采用仓库内源码快照 src/TinyHarness，并把主工程与测试工程目标框架统一到 net10.0-windows。工程和程序集命名为 TinyHarness，展示名称为 Tiny Harness，命名空间为 TinyHarness；保留 Loom-X 来源信息，记录原始摘要与本地摘要。复制时排除 bin/obj。通用 Harness 不放磁盘业务。

比较过三种方式：

- 直接引用本机 Loom-X 的 csproj：接入短，但 CI/其他机器不能独立检出构建，且上游未提交改动可能影响本项目。
- 将 Harness 移植到 net8：保留旧框架，但产生长期维护分叉。
- 固定源码快照并升级 .NET 10：复用当前实现、构建可移植，选择此方式。本机已具备 .NET 10 SDK。

只复用 Harness 本体；LoomX 的模型客户端位于宿主工程且耦合网关执行管线，不能当作 Harness 自带能力整体复制。SpaceMonger 用自己的 IModelClient 适配当前 Anthropic 兼容端点。既有配置、加密存储与本地化继续复用。

框架升级需验证 WPF/SkiaSharp 真正绘图，不能仅凭编译。既有 SkiaSharp/OpenTK NU1701 警告记录为基线；若升级后发生真实渲染问题，在相同范围内修复依赖或适配，并用界面证据验证。

## 运行边界与数据流

右侧 ChatViewModel 负责输入与消息投影；会话门面负责当前上下文、任务模型选择、运行互斥、AgentSession 和工具注册；AgentLoop 负责模型/工具循环。WPF 适配负责 Dispatcher 与窗口状态更新，Core 中确定性服务负责真正的查询、扫描和清理。

流程：用户输入或手动分析 → 会话门面 → AgentLoop → IModelClient → 原生工具调用 → 本地服务/主窗口适配 → 结构化结果 → 同一 AgentLoop → 流式回答。

- 模型输出中的普通 JSON 不再具有执行意义，只有已验证的原生工具事件能触发执行。
- 工具结果必须在真实操作完成后返回；扫描不能仅返回“已发起”就假定已完成。
- 每次工具调用读取最新的扫描会话、视图根节点和选择项；工具执行期间保存当前 runId/扫描版本，防止旧异步回调污染新结果。
- 对话保留 user/assistant/tool 完整协议历史；手动分析采用同一运行时的独立任务上下文，避免把原始分析历史带入对话白名单之外。对话排除规则改变时重新建立后续模型上下文；取消后的悬挂调用由 Harness 修复，不能拼接为假 user 观察消息。
- 模型客户端增量解析 SSE 与工具参数，处理多行 data、分块参数和完成/错误事件；在参数完整且合法前不发布执行事件。
- 模型的实际正文和思考增量独立投影，正文可在工具前后交替出现。启用思考时按端点协议处理合法内容，不把工具日志伪装成模型思考。
- 日志只记录运行标识、工具名、状态、耗时和计数；不记录消息、工具参数、密钥或原始响应。

## 磁盘工具约定

工具命名在实现时与现有查询保持一致；下表规定能力与数据责任，不要求多套重复工具。

| 能力 | 输入 | 完成结果 | 执行约束 |
| --- | --- | --- | --- |
| 读取上下文 | 无或范围标识 | 扫描根、当前目录、选择项、统计、建议状态 | 无扫描时也能执行 |
| 解析路径 | 路径文本 | 规范化路径、存在性、允许范围 | 环境变量按现有 ScanPathResolver 处理 |
| 扫描 | 目标路径 | 会话版本、完成/失败/取消、统计与根路径 | 复用 IFileScanner，支持取消和真实等待 |
| 查询树 | 路径/查询/数量上限 | 大文件、子项、匹配项、摘要 | 复用 IFileTreeQueryService，限制输出体积 |
| 定位与视图 | 已扫描路径、Treemap/TreeView | 实际显示路径、视图、选中项 | Dispatcher 更新，范围外明确拒绝或建议扫描 |
| 分析证据 | 当前扫描范围 | 元数据摘要、候选特征、安全限制 | 复用 RecommendationEngine 确定性部分，不调用另一个模型循环 |
| 发布推荐 | 当前扫描版本、候选数组 | 发布后的 ID、接受/过滤数量与原因 | 本地验证路径/范围/保护，复用现有列表 |
| 查询/选择推荐 | 当前 ID 集合 | 实际选中与过滤结果 | 不直接删除 |
| 执行清理 | 当前推荐 ID、清单版本、删除方式 | 逐项状态、实际释放量、刷新结果 | 批准绑定具体清单，执行前重新校验 |
| 用户输入/确认 | 必要问题或具体操作摘要 | 用户回答、拒绝或取消 | 一次决策一个入口，不反复确认内部步骤 |
| 技能读取 | 现有技能 ID | 可用技能与内容 | 复用当前技能目录，不导入 LoomX 网关技能 |

模型只能提出推荐，不能直接决定本地的路径权限、安全等级或已批准清单。各工具的参数投影需明确允许显示/回传的字段，避免 Harness 默认隐藏行为把后续可用上下文清空，也避免将凭据带入记录。

## 推荐与手动操作的统一

手动扫描仍直接使用共享扫描能力。用户点击分析按钮时，通过门面发起一个带明确任务边界的 Harness 运行，使用 AnalysisModelName；普通对话使用 ChatModelName。两者共享工具定义、上下文与推荐发布逻辑，复用现有加密 API 配置。

若用户在对话中发起分析，则当前 Agent 查询证据并发布推荐，不执行嵌套 Agent。手动分析和对话任务不能同时改写同一扫描/推荐状态；出现冲突时展示正在运行的任务，可停止后继续，不静默覆盖结果。

保留白名单匹配、系统/用户路径保护、内容指纹等已有确定性方法。旧的“请求模型 → 抽取 JSON → 独立返回列表”流程完成替换后删除，避免 UI 与 Agent 各看一份结果。

## 清理批准与状态更新

共享清理入口先将当前建议 ID 解析为本地持有的清单，并规范化路径、确定删除方式、统计总量，生成清单版本。确认卡呈现这些事实，不使用模型提供的总量作为执行依据。

用户批准只绑定该快照。确认等待期间若扫描/建议改变或删除模式改变，原批准失效；执行前再次验证当前清单与路径保护。拒绝/停止返回明确结果，禁止启动删除。真正执行使用 ICleanupService，之后复用树图、推荐列表和状态栏刷新，并将成功/失败/跳过项返回当前循环。

避免同时显示 Harness 通用批准卡和旧主窗口确认框；统一到一个确认入口。临时 UI 选择与导航不需要逐项批准，清空会话/覆盖分析的提示遵循具体影响。

## UI 设计与 tokens

主窗口结构：路径与工具栏位于磁盘区域；Treemap/文件树和推荐仍保留既有关系；右侧 Copilot 独立滚动和调整宽度。当前主题编辑、明暗切换、面板开合均继续工作。

面板从上至下：

1. 简洁标题栏：Copilot、运行状态、新建/清空入口。
2. 消息阅读区：用户短气泡；助手正文以 Markdown 排版；正文之间按真实顺序插入过程组。
3. 过程组：默认收起的“正在查询/已完成/失败”行，淡竖线连接工具；展开可查看参数与结果摘要，完整路径换行而非撑宽。
4. 按需出现的批准/必要输入卡：清单、影响、继续/取消。
5. 底部单一输入卡：上方多行输入，下方上下文/技能、模型信息、发送/停止；Enter 发送，Shift+Enter 换行，保留现有补全交互。

优先映射现有 VP.* 语义 token，必要时添加聊天 token，不为整张面板硬编码一套独立主题。参考 LoomX 的视觉关系：

| 类别 | 设计 |
| --- | --- |
| 表面 | 明色冷灰底/浅白面，暗色深蓝灰底/较浅表面；保留用户当前主题覆盖能力 |
| 强调色 | 默认参考明色 #2563EB、暗色 #60A5FA，业务颜色经语义 token 提供 |
| 边框 | 低对比细边界，过程竖线比卡片边框更淡 |
| 圆角 | 主输入/批准卡约 14px；图标操作约 9px；过程无厚卡片 |
| 排版 | 正文约 13px、过程约 12px，优先 Segoe UI/Microsoft YaHei UI，代码使用等宽字体 |
| 间距 | 基于 4/8/12/16px；窄面板优先换行与折叠 |
| 状态 | 等待、运行、完成、失败、取消分别表达；没有真实百分比时不展示虚构进度 |

正文在用户贴近底部时跟随；用户向上阅读则保持位置并提示可跳到底部。逐 token 更新合并到合理的 UI 调度节奏，避免反复重建整份 Markdown 引发卡顿。展开状态和滚动位置不能被后续增量重置。

## 错误与取消

- 运行使用关联 CancellationToken，贯穿模型、扫描、工具与批准等待。
- 单次模型失败遵循 Harness 的有限重试；已执行的磁盘工具不因网络重试而重复执行。
- 非法工具参数返回结构化失败，允许 Agent 修正；危险参数先本地拒绝。
- 限流、鉴权、超时、连接与服务端失败映射到中文摘要；上游详细信息先脱敏再显示。
- 停止后保留已产生的正文与工具结果，并标记停止；下一轮不把取消误当成功。

## 交付顺序

1. 在确认范围后固定 Harness 快照，升级目标框架，完成 IModelClient 与会话门面，先用协议测试证明真实 streaming/tool calling。
2. 接入共享扫描、查询和导航；将工具实际结果返回循环，验证无扫描起步与取消。
3. 统一推荐发布与清理批准，拆除旧提案/文本协议/延迟播放；回归现有路径保护与白名单。
4. 按 AgentEvent 重整消息模型与右侧 UI，并完成明暗主题、窄宽度、滚动、技能上下文回归。
5. 运行必要回归与独立验收，发布到 outputs/SpaceMonger-Copilot_yyyy-MM-dd_HH-mm-ss（上海时间），验证实际 exe 路径与应用窗口。
