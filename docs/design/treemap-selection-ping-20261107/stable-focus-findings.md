# 定位回摆调查与已确认修复

## 实际证据
- 来源为上一发布包 ping-frame-clamp-acceptance/frames.json，真实 079.bin 从 1x 定位到 22.17x。
- 第一段动画约 487 毫秒到达；目标旧布局坐标约 (807.56, 288.75)，屏幕位置约 (767.0, 199.3)。
- 约 561 毫秒提交目标倍率 LOD 后，目标逻辑坐标变为约 (809.30, 290.28)，同倍率屏幕位置突然变为约 (805.7, 233.3)。
- 宿主随后以新几何再启动一段动画，到约 943 毫秒才到达最终屏幕位置约 (773.3, 201.0)。
- 因此旧验收只证明 pan 位于边界和最终提示停稳，未覆盖布局提交前后的目标反向回摆。

## 因果链
- SquarifiedTreemapLayout 的根内边距、目录标题及内容预算依赖 zoom；改变 LOD 倍率会改变真实布局几何。
- FocusPathAsync 先对旧几何 tween，再等待 PendingZoomUpdate；几何变动后重复 FocusNodeAsync。
- 第一段最终 zoom 触发 ZoomChanged 和后台布局提交，目标发生位移，重复定位补救造成第二次拉回。
- CalculateFocusViewport 已使用原地图钳制；并非简单保留旧越界 pan 常量。

## 已确认方向
- 后台先准备目标倍率的稳定聚焦布局和最终钳制落点；开始一次镜头追踪时不再等待下一次 LOD 才修正目标。
- 准备期间保留旧画面；布局接管借用已有画面交叠能力保持连续，避免硬切。普通定位结束不再重复提交相同目标倍率布局。
- 回归必须覆盖真实布局引擎、右下角小目标、布局提交时目标轨迹连续、不回摆，以及取消和重复定位。
- 删除右键 Ping 调试菜单，保留推荐和引用定位。
- 不改选择、手动推荐、忙碌 toast、原地图边界、FEA400/800ms 单次冲击；不 Git 提交或合并，不清理旧产物。

## 当前实施与证据
- 用户确认后，最终 LOD 几何在后台收敛，只在运动前提交一次；旧截图覆盖准备阶段，交叠过渡后释放。真实 079.bin 的49个放大采样帧保持相同几何与单次提交，不再出现上一包的两段拉回。
- 回归发现首次 Arrange 的 SizeChanged 延迟事件在尺寸与已知值相同时仍会增加布局 generation，使准备结果被拒绝；真实诊断为开始 generation=2，相同 811×294.5 事件导致 generation=4。现在相同尺寸直接忽略，真正尺寸变化仍会作废旧结果。
- 准备返回空结果和动画中外部取消分别曾遗留旧 SKImage，新增测试先 RED 复现后补齐释放；最终228项聚焦回归通过。正式独立验收另由本候选 Runtime 保存，不以此文替代。
