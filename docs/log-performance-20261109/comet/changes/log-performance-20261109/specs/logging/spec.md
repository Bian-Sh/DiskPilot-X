# 日志系统完整规格

## 缓存与刷新

普通日志采用线程安全采集，不逐条向 Dispatcher 投递。界面以约 200 ms 合并刷新，每次更新必须有数量和时间预算，不能在持续生产时无限消费。历史和待处理数据同时限制条数与文本总量；为界面截断超长消息，不截断对应落盘消息。清空只清界面，不删除文件，并覆盖尚未显示的旧日志。隐藏控制台停止集合更新，重新打开取最新有界快照。

## 视图与交互

WPF 日志列表使用回收虚拟化及受约束滚动视口，只实例化可见内容。维持现有主题、透明背景和日志语义色。支持文本搜索、Verbose/Debug/Info/Warning/Error/Fatal 筛选、日志数量、复制、右键清空及回到最新。用户向上阅读时暂停尾部跟随，新日志不改变其阅读位置；切换面板保留跟随状态。单条超长日志显示有限预览，完整文本在文件中可查。

搜索框为圆角，框内左侧暗淡的“搜索”为 placeholder，空内容时右侧显示搜索 icon；有任何输入内容时搜索 icon 消失并显示圆形背景清空 icon，点击一键清空，焦点留在输入框。搜索保持即时匹配显示文本或来源，去掉首尾空白并忽略大小写。文案遵循应用语言资源。

工具栏不显示文件夹 icon，“打开日志目录”放在右肩“...”菜单。原 xx/yy 位置显示多组日志等级 icon 与条数；菜单中勾选哪些等级就显示哪些组，同时筛选列表，默认 Info/Warning/Error/Fatal。各组按当前搜索条件在有界显示缓存内计数，勾选等级即使为 0 条也显示，不勾选则隐藏；搜索、等级选择、新增与清空日志时同步更新。六组及窄窗口不与搜索框重叠，不引入空闲刷新。

## 文件格式与生命周期

普通日志必须落盘，不以界面缓存作为持久化。使用 .tsv 扩展名、UTF-8 BOM、中文列头和 Tab 分隔符；列包含时间、等级、进程、来源、消息、异常类型和异常堆栈。字段含 Tab、CR、LF 或双引号时按标准引用字段编码，双引号转义为双写，标准 Tab 分隔解析器能还原原值。不同进程不能竞争同一非共享缓冲文件；按日期、大小滚动并保留合理历史数量。平时缓冲输出并周期刷新，退出刷新；崩溃时尽可能刷新普通日志，但独立报告不能依赖其成功。写入失败必须能从独立诊断读到，且不递归调用故障输出链。

## 崩溃诊断

保留 Dispatcher 和 AppDomain 未处理异常的独立可读报告与 MiniDump。增加 UTF-8 BOM、列头、Tab 分列的崩溃 TSV，字段含时间、来源、进程、异常类型、消息、完整堆栈及运行环境。报告直接同步写入并刷新，失败必须被隔离，不依赖 UI 队列。可恢复的未观察 Task 异常只记录自身事件，不占用永久全局一次性门闩，真正未处理异常仍可被记录。MiniDump 失败时保留具体错误。无法保证系统掉电、强杀或严重内存不足下的全部诊断成功，不作虚假保证。

## 验证与交付

验证十万条洪峰、持续生产、超长内容、并发、清空、隐藏、打开、反复切换和历史滚动。真实非提权发布包通过 UI 操作和窗口截图验收，截图仅应用窗口。TSV 经标准解析器验证，受控崩溃只作用于任务自建验收进程。发布包包含运行时 DLL、Core 和 skills，禁止单文件、裁剪和 ZIP；测试 EXE 是 asInvoker，用户 EXE 是 requireAdministrator，均实读内嵌清单。发布环境执行只读源码规则，验证成功和完整失败诊断。每项验收由独立只读 Verifier 根据当前候选与证据判定；未执行和受阻内容不算通过。用户接受结果前不擅自归档或交付 Git 合并。
