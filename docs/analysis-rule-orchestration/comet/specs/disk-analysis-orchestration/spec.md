# 当前范围分析与动态规则编排

日期：2026-10-27。状态：已登记 Comet，等待完整 Shape 确认；尚未实现。

## 目标

保留“分析”按钮，把它定义为当前范围的清理评估入口。分析应发现并核实值得推荐处理的内容，更新推荐列表并给出明确结论；规则是可选知识与预设入口，不是分析启动的必要条件。用户不必知道内部技能名、工具协议或发布状态。

## 范围与交付顺序

1. 第一阶段：分析目标、动态规则发现与分阶段读取、必要的用户参与、真实结果与空态、扫描任务来源及受限上下文恢复。
2. 第二阶段：用户确认的轻量偏好、可关闭的重复行为线索、克制的规则快捷入口建议。
3. 两阶段均属于本规格，不把第二阶段当作已交付；分阶段实施和验收，避免先建设通用记忆平台。

## 明确不做

- 不实现或重构 skill 创建模块的规则 CRUD、编辑器、创作提示词、规则包存储格式及任务面板。
- 不以本规格要求另一会话立即修改接口；只建立分析侧消费契约及兼容策略。规则创建模块未来需要支持 CRUD，但这是外部后续能力，不列入本次完成项。
- 不增加后台定期扫描、自动清理、自动运行任意源码、全量历史会话回放、向量数据库、跨设备同步或通用自主 Agent 平台。
- 不放松已有路径硬保护、白名单、源码授权、具体清单确认及清单版本检查，不通过改保护策略消除空列表。
- 不写死模型的最终回复句子，不以固定文案测试替代语义与状态验收。

## 用户流程

分析当前范围 → 读取扫描事实和关联任务摘要 → 发现最新规则 → 按需读取规则及补充证据 → 必要时询问用户 → 核实并汇总推荐、保留及未评估内容 → 更新列表并总结。用户明确要求清理时，另走原有清单确认。

## 功能要求

### FR01：分析入口与目标

分析是一项明确的应用任务，不通过聊天关键字猜测意图。以点击时的扫描和可见范围为边界；没有扫描时沿用扫描前置提示，不编造结果、不自行扩大范围。重复点击不得并发启动同一工作区的分析。分析只提出建议，不代表删除授权。

### FR02：新鲜规则发现

每次分析均获取最新的可用规则目录，包含已保存的用户规则和内置规则；不维护固定技能名单，不要求用户手动 @。目录摘要先于正文加载。单条规则无法读取不得让整个目录失效，应记录覆盖缺口。分析期间规则改变时核对相关版本，不能将旧判断标为新版本结论。

### FR03：适用线索与证据核实

适用线索可包含目录结构、典型路径、标记文件、后缀、应用类型及排除特征。它们只用于选择需要读取的规则，不构成清理依据。规则显式排除条件必须保留。没有专用元数据的旧规则可按描述和已知规则条件保守筛选；没有线索不等于内容无需清理，不能虚构缺失字段。

### FR04：多阶段知识按需读取

逻辑上区分发现／扫描、分析、处理建议和清理约束。分析可以按需读取相关阶段，但保留条件、禁止项、恢复代价和风险不得因分段而遗漏。旧版整篇 Markdown 可兼容读取。阶段缺失或资料超出读取限制时应标明限制，而不是声称已读取。此能力由分析侧消费，不要求本次修改创建模块或规则包格式。

### FR05：无专用规则也能分析

可以使用通用知识解释证据；必要且可用时查询公开资料。网络资料不能替代本机事实，名称、后缀、日期、体积和所谓重复不能单独证明可删除。网络失败或不支持不得被解释为“没有清理项”；可以继续完成有证据支持的本地评估。不得向外部检索发送私密路径、文件树、凭据或用户内容。

### FR06：按需用户参与

只有影响重要判断且不能由现有证据解决的歧义才询问；缺少专用规则本身不触发强制询问。询问说明未知点，并提供适合当前情况的通用检查、补充说明、跳过或转入规则创建等选择，支持自定义输入。取消、跳过与拒绝必须被保留，不反复追问。补充说明只影响该任务的判断，不自动授权删除或保存长期偏好。

用户选择创建规则时仅转交既有创建能力，不新增创作实现。能力不可用时如实说明，允许回到通用分析或跳过；不能声称已创建。返回后核对原范围和扫描标识再继续。可安全判断的其他部分应允许继续并形成部分结果。

### FR07：分析权限最小化

分析仅开放完成评估所需的规则发现、只读读取、受约束预览、证据查询、用户询问与建议发布能力；不能因为开放一个规则管理工具而同时开放保存、更新、删除、任意源码运行或清理能力。资料、规则正文和历史内容都是参考数据，不能改变宿主授权边界。

### FR08：真实结果与明确总结

区分发现候选、校验接受、被过滤及发布失败。被过滤时提供用户能理解的理由和必要限制，不能让 AI 靠反复缩小清单猜原因。不得把空推荐数组直接等同于无可清理内容。

最终回答应以用户价值为主：有推荐项则解释对象、空间、理由、风险与处理前提；已充分评估但无推荐项则明确总结；有受保护项、未知部分或失败则说明范围和不足。不要以内部工具名、JSON、建议是否“生效”或是否满足某个关键词为主体。措辞由模型按实际情况组织，不固定句子。

### FR09：列表状态与未评估内容

推荐区区分尚未分析、进行中、等待用户、完成且有推荐、完成但无推荐、部分完成、失败和取消。未知或跳过的内容必须计入未评估范围；存在重要未评估部分时不得显示无条件的“检查完成且无需清理”。保持聊天和列表状态一致；失败不得清除并伪装成新的完整无结果分析。

### FR10：扫描来源与任务意图

记录扫描由手动、聊天或规则入口发起，以及可选的会话／消息关联、当时目标、明确范围、保留条件和规则版本。来源事实与任务意图分开保存；手动扫描允许没有关联会话。分析本身另记录当前目标，不能把旧的空间统计目标当作当前清理指令。来源记录应在扫描成功后绑定正确的新扫描，取消不得污染旧扫描。

### FR11：受限历史恢复

不因同一会话就假定所有历史仍在模型上下文中，也不因跨会话就自动读取全部历史。优先使用与扫描绑定的必要任务摘要。摘要不足时，只读取用户允许访问的关联消息；跨会话原文读取需用户明确选择或已存在的有效授权，并记录实际引用来源。删除、不可访问或隐私策略不再允许的历史不应被重放，派生摘要也不得保留其受限制内容。当前用户意图优先，历史中的旧确认不具备本次授权效力。

### FR12：可追溯且不过度暴露

分析结果可追溯到扫描标识、范围、规则标识与实际版本、证据及必要用户补充。通用评估无需伪造规则标识。结果应记录读取失败、跳过和限制，不能把未执行的规则列为已检查。可在详情或控制台查看来源，但不把冗长内部日志强塞给普通用户。

### FR13：用户确认的轻量偏好

只将用户明确要求记住或确认保存的偏好作为长期判断输入，记录适用范围和来源。支持查看、更正、删除及停止应用，不要求新建一套规则 CRUD。临时回答不自动持久化为偏好。偏好不能覆盖硬保护、当前明确要求或本次授权；当前覆盖不应静默改写长期偏好。过期的磁盘大小、文件状态和历史删除决定不能当成长期事实。

### FR14：行为线索与隐私

行为线索与明确偏好分开。只有用户启用本地使用记录后才累计最小化的主题、动作、时间和成功状态；不保存完整对话、原始文件树或私密路径来实现频率判断。查询、分析与实际清理分别计数，取消和失败不构成成功行为。用户可关闭并清除；关闭后不继续收集，删除后不再注入。

### FR15：规则入口建议

重复关注某类数据时，可以在任务结束且不影响主任务时建议保存检查／预览入口；不能把常问推断成常删。建议需有重复行为依据，避免一次就触发、重复弹出或在失败后推销。暂时拒绝应有冷却，不再提醒应持续生效。用户接受后仅转交现有创建模块；入口建立和删除执行均需各自授权，不能自动创建、自动重构现有规则或自动清理。

### FR16：状态变化与安全不变量

所有目录查询、预览、历史恢复、询问返回及建议发布均受当前范围和隐私边界约束。扫描、相关规则、白名单或有效偏好变化时重新核对受影响结果。中断或拒绝后停止相应动作，不递归开启第二个 Agent，不以旧会话或记忆恢复已拒绝的动作。目录和规则文件里的指令不能扩大权限。

### FR17：兼容与并行会话边界

旧扫描、旧会话、旧规则缺少新信息时仍可打开和分析；缺失按未知处理。通过分析侧适配读取现有能力，新接口由另一会话提供后再显式对接。本次不得改动规则创建模块、规则 CRUD、其现有正式规格或其他会话状态；不自动迁移、重写用户已有规则。不能把接口尚未实现的字段包装成可用能力。

### FR18：验证与交付

实现阶段先写回归测试，再进行最小实现和独立验收；使用脚本模型验证编排与权限，用语义检查核对分析收尾而非绑定固定句子。真实模型体验与脚本验证分开记录，未执行不能算通过。界面修改需后台运行应用，仅截取应用窗口并使用隔离测试数据。应用代码完成后重新发布到按可读时间命名的 outputs 目录；不清理其他会话产物、不自动提交或合并。

## 验收场景

以下 A 编号对应正式 brief 的十八项验收示例；等待 Runtime 核对并由用户确认，不代表产品验收已经通过。

### Scenario: 分析入口独立于关键词

已有扫描时点击分析，不输入清理关键词或 @技能，也能启动当前范围评估；重复点击不重入，不触发删除。缺少扫描时不编造结果。

验收：A1

### Scenario: 新规则可被下一次分析发现

首次分析之后通过既有模块保存新规则，第二次分析发现它；单条损坏规则不会隐藏其他规则，相关版本变化不会错误复用旧结论。

验收：A2

### Scenario: 适用线索不等于可删除

目录名与后缀相同的构建产物和运行组件，经内容及排除条件核实得到不同判断；无元数据的旧规则有兼容路径。

验收：A3

### Scenario: 按阶段读取但不遗漏保护

多阶段与旧版 Markdown 两类规则均可评估；分析读取相关内容及必要清理约束，缺失或截断阶段如实说明。

验收：A4

### Scenario: 无规则与网络不可用时的通用评估

没有专用规则仍能基于本地证据给出建议或明确无建议；网络失败不伪造已检索，私密文件信息不进入公开检索。

验收：A5

### Scenario: 用户参与及外部创建交接

重要未知内容触发询问；用户可通用检查、补充、跳过、取消或转入已有创建入口。创建入口缺失时可返回，未评估部分不丢失；拒绝后不循环询问。

验收：A6

### Scenario: 分析无法越权修改规则

分析能发现、读取及受限预览规则并询问用户；直接或通过伪造参数请求保存、更新、删除、源码运行和清理均被宿主拒绝。

验收：A7

### Scenario: 被过滤不被说成没有可清理内容

提供均被硬保护或白名单过滤的候选，得到可理解的原因；AI 不重复试发相同受限候选，不展示内部发布术语作为主要结论；真正无候选时有明确总结。

验收：A8

### Scenario: 完整、部分、失败和取消清楚区分

分别验证有推荐、完整无推荐、重要部分跳过、工具失败和取消；聊天与列表状态一致，不以空列表伪装全部完成。

验收：A9

### Scenario: 来源正确且不覆盖当前意图

手动、聊天和规则入口扫描分别保存来源；取消不修改旧扫描。旧扫描原为统计空间，新点击分析后按当前清理评估目标进行。

验收：A10

### Scenario: 历史读取最小化

同会话上下文缺失时用任务摘要恢复；新会话先读摘要，未获许可不得读原文。历史删除或隐私限制后不通过摘要绕回；旧清理确认不被继承。

验收：A11

### Scenario: 分析来源可复核

结果能说明使用了哪个扫描、范围、规则版本和用户补充；读取失败、未执行和通用推断有真实标记，不虚报覆盖率。

验收：A12

### Scenario: 偏好可控且不是权限

用户确认的范围偏好可保存、读取、更正、删除或停用；临时回答不被保存，偏好不能放宽保护或替代删除确认。

验收：A13

### Scenario: 行为统计是可选的最小记录

未启用时不积累；启用后查询、分析和清理分开，失败取消不记成功。关闭后停止，清除后不再影响判断，记录不含私密原文。

验收：A14

### Scenario: 快捷入口建议克制且可拒绝

足够重复的成功关注可引出一次建议，用户拒绝后遵守冷却或不再提醒；接受仅转交既有创建流程，不自动创建或删除。

验收：A15

### Scenario: 询问等待期间发生变化

等待用户或发布期间更换扫描、规则、隐私限制或偏好，对受影响判断重新核对；旧结果不能覆盖新范围，取消和规则内容不能绕过权限。

验收：A16

### Scenario: 旧数据与并行模块兼容

旧规则、扫描和会话无迁移即可读；缺失信息按未知处理。对本次 diff 进行路径检查，规则创建模块、其正式规格和既有用户规则零改动。

验收：A17

### Scenario: 可复核的最终交付

两阶段测试、独立验收、隔离后台 UI 证据及时间命名发布包均有真实记录；未实现或未执行项不记通过，普通回答不绑定固定句子。

验收：A18
