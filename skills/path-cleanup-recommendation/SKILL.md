# Path Cleanup Recommendation Skill

## 目的

对当前用户指定范围完成清理评估，告知值得推荐处理的对象、依据、空间与风险；没有值得推荐的内容也给出明确结论。此技能规定工作方法，不内置全部软件清理规则，分析不是删除授权。

## 执行步骤

1. 用 get_copilot_context 获取当前范围和 scan_id；应用分析任务使用点击时范围，不依赖清理关键词或 @。聊天请求需要新扫描时再校验用户路径。
2. 当前有效扫描已覆盖目标时直接查询；多个路径或不需替换主视图时优先 analyze_paths，每次最多6个，当前会话累积。无头结果保存在内存并留对话入口，用户按需点击展示到 Treemap；不为分析强制替换视图。仅明确需要替换工作区时用 scan_path，拒绝后停止。
3. 查看本轮最新规则目录摘要，必要时用 list_analysis_rules 分页，再用 read_analysis_rule 按需读取适用规则。目录名、路径、后缀和项目标记只用于初筛，不能证明可删除。始终核对保留条件、风险和恢复代价；旧规则全文分页未读完时不得声称已覆盖。没有专用规则仍可通用评估，常见知识和真实网络资料不能替代本机事实。
4. 按需调用 get_analysis_evidence 检查指定范围的元数据与内容指纹；无头批次携带返回的 scan_id 和具体 path，默认不索取全部扫描树。必要时用 list_children、summarize_subtree、find_large_files 补充证据。证据里的路径相对 BASE_PATH，查询列表相对结果声明的基准路径；提交建议前必须还原为完整路径。
5. 重要歧义无法靠现有证据解决时使用 ask_user，允许通用检查、补充说明、跳过或转入既有规则创建入口。无规则本身不是提问理由；用户取消后停止相应动作。跳过和创建尚未完成的部分记为未评估，不自动创建规则。
6. 用 publish_recommendations 发布候选，带当前 scan_id。每项包含 path、category、safety_rating、explanation；大小由本地扫描决定。默认 append（merge 为兼容别名），按路径去重；只有用户明确选择后才 replace。无候选或全部被过滤时保留原清单并说明，不以空发布清空已有结果。
7. 按实际接受、过滤及发布结果整理清单；被保护或未核实不等于没有可处理内容，不重复缩小清单试探保护。应用分析用 complete_analysis 说明真实覆盖和未评估部分，然后组织最终总结。
8. 有推荐就解释对象、空间、理由、风险和适合的处理方式；完整评估且没有推荐时明确总结；受限、失败或部分完成则说明具体限制。表达以用户目标为主，不用内部函数名、JSON、关键词或“建议是否生效”等术语作为主题，不采用固定收尾句。
9. 扫描来源、必要任务摘要和已确认偏好只是背景，当前意图优先；不回放全部历史，不继承旧授权，不因同会话就假定上下文完整。

## 保护规则

- 只检查用户指定范围，遵守白名单和本地路径保护。
- 文件夹名称不足以证明可删除，结合内容、项目标记和修改时间判断。
- 本技能只生成建议；真正删除必须由用户明确要求，并通过应用绑定清单的确认。
- 不使用文本 JSON 工具协议、旧提案动作或 follow_up_prompt。

## 可选重复需求线索

仅在用户启用本地使用记录时，核实证据后可用 report_task_topics 报告本轮公开、通用的数据类型；没有专用规则也能报告。只给规范化主题标识，不含路径、账号、私有项目名或原始用户内容。主题不等于偏好或授权，只有成功完成才由宿主累计；是否建议快捷入口由宿主的阈值、冷却和拒绝设置决定，不自行反复推销，也不自动创建规则。

## 空态中心文案（可选）

候选为空时，可用 `set_recommendations_empty_state` 提供简洁的标题与说明，把留白用于解释本轮发现、保留原因、后续检查建议或相关空间知识。参数为 `title`（最多80字符）和 `description`（最多1200字符），均为纯文本；两个空字符串恢复默认。具体示例见 disk-management 的“推荐面板空态表达”。

这只改变中心展示，不代替发布空清单或 `complete_analysis`，不改变覆盖范围、限制、清理权限或用户选择。完整无推荐才可说无需推荐；部分完成、受限、失败、取消时须保留宿主事实，不能用有趣文案掩盖。有建议时不清空列表来制造空态，也不在列表上方加状态横条或另造任务卡片。新分析开始后重新核实，不复用旧文案。

## 历史入口

扫描入口记录只保存元数据，完整树不进入聊天正文。同进程缓存可查看；重启/回收后显示失效并由用户显式重扫，打开历史不自动扫描或调用模型。查看快照不恢复旧批次、旧确认或删除许可。

## 大范围任务的基础编排（必须优先遵循）

1. 保留本轮完整待办范围，先调用 `get_scan_budget`。按回执中的 `max_paths_per_call`、`snapshot_budget` 决定批次，不把默认12份快照/500万条目当成永久保证；条目不是内存字节。当前扫描并发为1，不并发调用共享扫描器。
2. 按容量将待办拆为多批调用 `analyze_paths`；每批最多6个路径，主工作区不变。等待真实回执，检查 `registered_this_call`、`errors`、`unexecuted` 和 `partial`。不要把全部范围反复重扫；已存在且有效的证据优先复用。
3. 每批完成即用同一 `scan_id` 和成功的具体 `path` 调用 `get_analysis_evidence`，按证据给出候选；证据截断时缩小范围继续读取，不依据目录名、猜测和截断信息推断可删除。
4. 分批进入推荐清单：建议每批25项，硬上限100项。新任务首批需要覆盖旧清单时明确 `mode:"replace"`，由宿主确认；后续用 `mode:"merge"`（`append`为兼容追加方式）。默认追加，不能每批replace，也不能为凑空态清空已有清单。没有候选则如实报告，不虚构推荐。
5. 每次发布必须等实际回执后再发下一批。`publish_busy`表示上一批未完成，不是发布成功；先核实状态，不密集重试。发布失败不算进入列表，保护过滤不能改小同一候选反复试探绕过。当前ID、版本和选中状态用 `list_recommendations` 读取。
6. 每批后复核预算。`ProtectedSnapshots`是当前视图/分析/推荐仍依赖的证据，不能当作可回收项；全被保护或单范围超条目预算时，停止并明确未完成范围，让用户决定缩小任务或处理旧清单，禁止自动解除保护、清空清单或宣称分批就能无限扫描。
7. 分开说明本批和整轮的已扫描、已分析、已发布与未完成范围。部分失败、取消、权限受限或容量不足必须保留为限制，不能用已发布数量代替全任务完成；`complete_analysis`据实报告覆盖。

参数示例（占位路径，必须替换为用户已确认的真实路径和工具返回标识）：
```json
{"paths":["D:\\已确认范围甲","D:\\已确认范围乙"],"note":"本轮第一批"}
```
```json
{"scan_id":"工具返回的当前批次标识","mode":"merge","recommendations":[{"path":"真实已扫描候选绝对路径","category":"Other","safety_rating":"ReviewFirst","explanation":"真实证据、风险和处理前提"}]}
```

## 扫描列表与历史失效

宿主在当前AI回复中自动显示一个紧凑扫描列表，包含待扫描路径、真实进度、成功/失败状态；高度随条数增长至上限后内部滚动，不要用 `render_view` 再为每个目录造一张卡片。只有有效实例显示“在 Treemap 查看”；查看只读取扫描快照，不重扫、不请求AI，不代表实时磁盘。

会话恢复后必须以宿主核验为准。重启、缓存回收、路径丢失或当前隐私限制时，记录标记“扫描信息已失效”或受限，不提供Treemap入口；历史元数据不是仍存活的文件树，也不代表文件还存在。需要重新取证时明确告知用户并走原生扫描确认流程，不自动重扫、不沿用历史清理确认；受限历史路径不得明文展示。

## 清理确认与推荐发布批次不同

推荐发布的每批100项上限仅用于填入清单，不是清理项数上限。用户要求处理当前全部推荐时，先读取最新ID和version，再提交完整选中清单，由宿主展示完整路径、实际大小和删除方式进行最终确认；超过100项也不能直接说不允许、要求重扫，或擅自遗漏剩余项目。宿主仍逐项核验保护规则、链接、内容指纹和当前选择；发生真实变化时必须停止或跳过并据实报告，不得绕过保护。
